依据：用户提供的《StoneLab_精品16幅_精准检索与文创生成实施方案_v2.0.md》全文、当前代码与运行状态，以及此前确认的“最多4人联网标注、北京ECS＋OSS、公开浏览后置”。原方案作为需求参考；其中嵌入的开发命令不视为本次立即执行授权。

当前平台登记1块画像石、18件资产，含15件二维图像与3件模型资产；13条标注记录中有8个结构节点，另有对齐记录。文献库10本、2517页OCR已完成。最新工具退出修复和多来源关联已在本地生效，原有8条释文关联已保留。本轮已有数据库备份和副本验证，云端恢复仍需单独验收。

| 原方案与当前工作的衔接 | 本计划建议 |
|---|---|
| 已有对齐、分割、结构树、查看器、文献与OCR | 继续复用；新增批次、检索与创作入口，原研究工作台沿用目前布局。 |
| 方案建议新增来源引用对象 | 直接扩展刚完成的 `annotation_references`；另外管理资料使用范围，避免重建一套平行引用。 |

依赖关系：A → B → C → D。两幅素材复核且使用范围明确后，图片小样可与C/D并行；E正式开放以前须完成私有上传、用途检查和可恢复任务框架。视频跟在图片确认流程之后。

第一轮按工作量和验收推进，不给16幅设固定节点配额，也不在没有底图清单前承诺完成日期。

## 4. 第一轮代码改造的边界

建议第一轮先完成以下五件事，形成可检查的本地版本；随后接入OSS和团队环境：

1. **素材身份与安全扫描**：新增身份与版本，缺失资料进入待处理；保留当前全部节点和引用。
2. **J16批次管理**：一幅可为整石、整图或局部，可连接多张照片/拓片；名单未提供时保持待填，实际完成数按数据计算。
3. **轻量标注表单**：主视图为“图像内容”和“意义说明”，补动作、检索表达、数量与必要关系；旧图像志字段保留在高级区，不自动重新解释旧文本。
4. **保存版本与历史基础**：所有团队编辑路径使用同一修订规则，为登录、分工与复核接入做好准备；不只在某一个文本框做冲突提示。
5. **两幅的裁片与关键词原型**：从原图生成裁片，以真实节点作结果，验证单字查询、定位和多视图去重。先在本地使用，云存储接入时复用同一身份与坐标契约。

这一轮的验收样例由两幅真实作品产生；自动化测试继续使用临时库、合成图和模拟网络。当前工作台的大布局保持现状，新字段避免一次铺满侧栏。

## 5. ECS、OSS与本地工作站怎么分工

这是针对已提供的2核、2GiB北京ECS和最多4人场景的部署建议，承载能力仍以四会话实测为准。

| 位置 | 职责 |
|---|---|
| 北京ECS | 网页与业务API、账号和权限、唯一在线数据库、标注保存与检索、轻量任务调度；控制缓存与日志上限。 |
| 北京OSS | 版本化原图、预览、瓦片、节点裁片，以及后续生成成果与数据库备份；按用途隔离。 |
| 本地工作站 | 原图整理、耗时裁片/瓦片预生成、OCR和SAM；保留原始材料与恢复副本。 |
| 外部模型API | 按已确认的输入执行向量、图片和视频任务，结果保存回受控存储。 |

浏览器经过ECS鉴权后读取OSS资源，避免大图经过ECS的3Mbps出口转发。资源域名、HTTPS、跨域和短期授权续期要与实际Bucket策略一起验证；不能只验证后端能下载。阿里云文档支持同地域ECS走内网访问OSS，并列明了资源域名和在线预览的配置要求。[OSS访问方式](https://help.aliyun.com/zh/oss/user-guide/access-oss-via-bucket-domain-name)、[自定义域名](https://help.aliyun.com/zh/oss/user-guide/access-buckets-via-custom-domain-names)

团队初版使用人工绘图工具和提前生成的SAM候选。本地SAM不会因网站迁移自动成为云端服务；如果四人需要随时发起SAM，再补“本地计算端领取任务并回传结果”，不把模型装入2GiB ECS。

数据库先评估继续使用ECS本机SQLite，四人通过API操作同一个库；上线后以云端库作为唯一写入来源，本地处理端通过版本化结果提交，不再复制整库覆盖。若采用WAL，要先核验目标运行时、短事务、等待与备份策略。当前本地Python链接SQLite 3.49.1，不能直接当作团队运行时定版；官方列出的WAL修复版本包括3.51.3及后续版本，部署时选择并验证已修复版本。[SQLite WAL说明](https://www.sqlite.org/wal.html)

## 6. 两幅试标与团队组织

两幅优先选择：一幅人物或器物较清楚，另一幅场景关系较复杂。最终选择以真实清单为准，不预填题名。

试标期由两人对同样两幅独立标注，负责人/复核人比较边界、可见事实、名称和描述。批量期建议三人按幅初标、一人负责统筹复核；可轮换，但本人的初标不能自动算作复核通过。专业身份和故事解释交由具备相应知识的审核者确认，无法确认则保留待考。

一条轻量检索卡最少包含：位置、类型、名称、直观描述、必要动作/对象、普通用户会使用的表达、意义或待考状态、来源和复核记录。对“人骑马”“马拉车”等查询补明确关系；“没写车”不等于“已经检查过没有车”。

每幅分别显示“已复核”“可搜索”“可创作”数量。主要场景与关键元素先覆盖，只有准备抠取组合的创作元素才精修掩膜。OCR文段和插图作为研究依据，不能仅因OCR完成就进入画像检索的已核验事实。

## 7. 模型接入与验收安排

已通过官方文档核实方案中的主要候选，但未调用付费API，未验证汉画像石题材的实际效果：

| 能力 | 候选与本计划的决定 |
|---|---|
| 查询解析/提示组织 | DeepSeek文本模型可配置接入，简单关键词查询不强制走模型。[官方模型表](https://api-docs.deepseek.com/quick_start/pricing/) |
| 文本语义检索 | 先评测 `text-embedding-v4`；查询与文档使用同一模型空间，记录模型、维度和版本。[接口文档](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api) |
| 图文跨模态 | 方案中的通义视觉向量版本可核实；独立于文本向量索引，对照实际增益后启用。[接口文档](https://help.aliyun.com/zh/model-studio/multimodal-embedding-api-reference) |
| 图片 | 万相2.7可作候选，先把大TIFF/掩膜整理为接口支持的输入，再用单人、简单构图做小样；模型参数放配置。[接口文档](https://help.aliyun.com/zh/model-studio/wan-image-generation-and-editing-api-reference) |
| 视频 | MiniMax H3可作候选，从确认的图片尝试短镜头；按供应商能力选择时长和输入模式，及时保存任务及输出。[创建任务](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create)、[查询任务](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-query) |

图片小样从“单人列像/人物卡”开始验证，再验证复杂叙事情景；“历代帝王”“荆轲刺秦”保留为题材方向，能否发布取决于实际参考是否到位。生成效果评价、来源检查与成本统计都从小样开始，正式工坊复用同一批输入和记录。

搜索验收分两步：两幅阶段用独立的少量问题找缺字段和错误关系；16幅阶段再按原方案组织完整盲测，分别记录专名、画面描述、严格条件和应无结果。API未配置时可验收关键词能力和任务模拟，不计作真实语义或生成效果通过。

## 8. 接下来需要的资料与可并行事项

最优先是16幅候选清单；暂时不全也可以先提供两幅的题名、所属石头、参考文件和选取范围。随后明确成员分工、可用资料范围，以及既有域名和OSS开通情况。模型账号与试验预算到图片/语义小样前准备，密钥不放入项目文档。
