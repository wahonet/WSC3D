# 武氏墓群石刻数字档案与图像研究平台

面向武氏墓群石刻的公开展示、图像研究与文献整理平台。文物档案、照片、拓片、三维模型、图像标注和文献出处通过稳定的文物编号关联，公开展示与研究工作台使用同一份资料。

项目提供 Windows 64 位便携运行环境，支持本机使用、办公室局域网协作及离线研究成果交接。基础浏览和人工研究可在本地完成，在线问答、生图及视频生成使用单独配置的服务。

**上一轮基线已完成（2026-10-01）**：精品16幅文创、全152件SAM3分割与证据关联、画像形象库、故事形象库和图文论文均已交付。当前正在开展[多批次图像对齐与分割版本关联](#multiversion-research)，原有成果和验收快照保留。新对话可从 [本轮成果与接手说明](#sam3-152-handover) 了解上一轮基线、代码入口和资料位置。

## GitHub 仓库与完整项目

GitHub 仓库保存程序源码、回归测试、项目配置、运行包校验清单和本说明。原始文物与文献资料、原图资源压缩包、研究数据库、模型权重、运行环境压缩包、前端构建产物、日志及本机 API 配置保留在完整本地项目中，不随源码提交。

下方的双击启动与整目录迁移步骤适用于完整项目。仅克隆 GitHub 仓库尚不能直接运行：需从完整项目副本补齐 `resources`、`data`、`models`、`runtime/resource-packs`（如已收纳原图）和与校验清单匹配的 `runtime/runtime.zip`、`runtime/development.zip`，再运行 `tools/构建前端.bat` 生成 `build/web`。在线服务配置在工作台重新填写。

## 快速开始

将完整项目放在本机可写目录，双击根目录的 `启动平台.bat`。浏览器默认打开 [本地平台](http://127.0.0.1:8030/)。首次启动会校验运行包并解压到 `%LOCALAPPDATA%\WSC-Unified`，后续复用缓存，无需另外安装系统 Python 或 Node.js。

| 操作 | 入口 |
| --- | --- |
| 本机启动 | `启动平台.bat` |
| 局域网启动 | `启动平台（局域网）.bat` |
| 停止平台与项目模型服务 | `tools/停止平台.bat` |
| 西长廊摆放 | `tools/打开西长廊摆放工具.bat` |
| 后展厅摆放 | `tools/打开后展厅摆放工具.bat` |
| 原版三维查看器 | `tools/打开原版三维查看器.bat`，默认端口 8040 |

首页默认进入公开展示。点击右上角登录入口进入研究工作台，默认账号为 `admin`，默认密码为 `123456`。可通过环境变量 `WSC_WORKSPACE_PASSWORD` 指定密码，启动、停止和命令行维护工具应使用同一设置。平台重启后需要重新登录。同一设备连续输错 5 次密码后，需要等待 60 秒才能再次登录。

局域网模式下，在主机用 `ipconfig` 查看当前 IPv4 地址，其他设备访问 `http://主机IPv4地址:8030/`。首次启用可能需要确认 Windows 防火墙配置，主机须保持开机并运行平台。局域网内的任何设备都能打开登录页，仍使用默认密码时启动窗口会给出提醒，长期使用建议设置 `WSC_WORKSPACE_PASSWORD`。需要恢复为仅本机访问时，先停止平台，再使用普通启动入口。默认端口登记在 `config/project.json`。

界面提供“墨石”深色与“宣纸”浅色两套主题，点击右上角的日月图标切换，选择保存在当前浏览器。顶栏同时放置平台名称、功能导航和 AI 提问框；窗口较窄时导航自动换到第二行。

### 图像标注与文献举证

1. 在“图像研究”选择文物和底图，通过手工绘制或分割取得区域；新绘制和分割结果先作为候选保存。
2. 在“结构标注”选中区域，填写名称、概念和描述；可选择相关故事、人物或物品，挂接题材及其文献。
3. 展开关联文献，选择原文并填入直观描述或故事描述。系统同时保存原书、页码、文段身份和摘录位置。
4. 点击“保存”或按 `Ctrl+S` 提交。正常保存后成为已审标注，并可出现在对应公开档案的图像解读中；未提交草稿不等于已保存成果。

“文献举证”用于查找本石关联原文、同题讨论及全库文字，点击页码可进入文献中心。文献页中的“关联图像”可返回引用该页的标注。

几何保存会检查形状、点数、维度和数值。遇到无效几何提示时，应修正区域再提交；历史坏几何不会阻断其他有效区域的投影和显示，原记录仍保留供核查。

### 文献整理与布局编辑

在文献中心打开 PDF 原页，选择合适的 OCR 引擎，识别后核对文字与插图并进行人工校订。重新 OCR 时，系统会协调既有人工内容和引用；未能可靠匹配的记录保留供复核。

文段校订与展厅布局均有版本冲突检查。多人同时处理同一内容时，若提示已被修改，应先保留自己的调整，再读取最新内容。西长廊摆放工具可先“导出JSON”备份草稿，再“读取系统布局”继续调整。摆放完成后须点击“应用到系统”或“保存到主平台”，浏览器自动保存的草稿尚未应用到平台。

### 画像形象库

公开入口为 `/#section=motifs`。按原石、类型和故事查找已命名的 SAM3 切图，详情可查看文献原文、书页插图及对应知识图谱。每个已确认关联的形象只展示一张卡片，优先拓片，无拓片时使用照片；其他来源集中在右侧“图像版本”。页面使用缓存 JPEG 和适合显示尺寸的透明掩膜，按可见范围加载；下载仍按验收来源导出原尺寸透明 PNG 与包含来源、标注编号、几何和引用的出处 JSON。

默认展示已审形象，开启“包含候选”可查看保留释读不确定性的形象。仅有位置范围、未经命名的模型检测及失效引用不作为成品切图展示。2026-10-04全152件核对：含候选共3,237个形象（含不同版本共7,762个切图），默认1,376个形象（2,629个版本切图）；数量包含人物、动物、器物、文字、局部和整体纹带。对象身份按已确认的原标注与版本关联计算，同名且位置不同的形象不合并。统计随候选开关更新，筛选结果同时显示对象数与版本切图数；新增标注后点击刷新更新成果和图谱。打开、切换来源或关闭详情保留列表位置及已展开的分页。

知识图谱以青色亮环标出已关联标注的节点，目录和详情显示关联数量，内部颜色仍区分故事、人物、物象和画像石。全景按概念实际使用次数显示；筛选单石后，只统计该石仍存在且未被驳回的图谱标注，不沿用其他石件的数量。亮环包含候选释读；“类型参照”关系明确显示为类型参照。

公开故事入口为 `/#section=stories`。原图场景按已保存的场景区域或轮廓切出，保留人物、器物与周围刻线；“形象组合”将该场景所属的 SAM 切图按原位置组合，未分出的区域透明。两种视图均不叠加标注框，区域裁剪与 SAM 轮廓的来源在出处 JSON 中分别记录。所属形象通过同石、同图的标注父子身份关联，可与单体形象库双向跳转。场景及所属形象的文献、插图和图谱可回查，候选释读与类型参照仍明确标示。

故事库同样按已确认的对象身份合并版本，每个故事只展示一张卡片，优先拓片，其他来源在右侧“图像版本”切换。2026-10-04全152件核对：含候选共529个故事（含不同版本共1,413个切图），默认308个故事（784个版本切图）；数量按已确认关联的场景位置计算。打开、切换来源或关闭详情保留列表位置及已展开的分页。候选切图与故事之间跳转时保留候选显示设置，PNG和出处JSON均可保存。核对及浏览验证记录见[双库显示与性能修复](resources/authoring/research/rear46-execution-20261003/library-ui-20261004/README.md)；2026-10-01历史验收数字保留在下文成果快照。

### 问答与分割

本地模型包括 SAM3、SAM3.1、MobileSAM 图像分割，RapidOCR、NDL、MinerU 文字识别，以及 BGE 检索、重排和 Ollama 本地问答。模型路径及路由登记在 `config/models.json`，实际可用方式取决于本机环境、显卡与驱动。

问答依据当前已登记文献与底本提供证据，原书缺失、OCR 不完整或候选未确认时，需要回查原页。问答结果目前不作为服务器端研究历史自动保存。公开问答会调用在线模型或本机显卡，因此每台设备每分钟最多提问 12 次，全平台同时最多处理 3 个提问，超出时提示稍后再试。

修改文段、完成 OCR 或登记扩展文献后，检索索引在后台更新，更新期间检索继续使用上一版索引；问答如提示“正在准备文献索引”，完成后会自动作答。

### 电子文创

电子文创只在传承中心的场馆局域网内提供给现场观众，观众端不调用任何在线模型，所有成品都在工作台预先制作和核对。每件成品都印有原石编号、出处和指向文物档案的二维码；AI 生成的上色画面在观众端始终标注“艺术演绎”，不作为研究结论。

**主题制作**（工作台“电子文创 → 主题制作”）：一个主题对应一块原石上的一个故事，按八步完成：

1. 立项：选择原石和已审标注，填写标题、引子和画面描述。
2. 原图：按标注范围从拓片裁出局部，作为线描、演绎和观众端“依据”的唯一来源。
3. 线描：生成 AI 线描候选，与原图并排或叠加核对，人工确认后选定；没有合格线描时可暂用去底拓片底稿。
4. 演绎：以选定线描为底稿生成上色图，最多选定两张，第一张作封面。
5. 动态：可选，挂接“动态短片”中已制作的视频。
6. 文案：引子、故事、原书出处与寄语。
7. 成品：选择配色，渲染手机壁纸、明信片、动态明信片、观展纪念卡、头像与表情包。
8. 上架：检查各步完成情况后发布，撤回后观众端立即不可见。

生成线描和演绎会请求 Seedream 并产生费用，其余步骤均在本机完成。未被选用的 AI 候选 30 天后清理，已选用的保留。

**观众端**（`/#section=creative`）：主题墙 → 主题页（原石依据、故事、线描与演绎）→ 带走页。观众可直接保存成品，或定制文字、配色后生成作品。文物档案、知识图谱、AI 问答和传承中心展厅介绍中，涉及已上架主题的位置会出现对应入口。

**场馆与现场**（工作台“电子文创 → 场馆与现场”）：设置观众访问地址、Wi-Fi、自助屏空闲复位时间和打印开关，下载展厅集章海报和主题海报 PDF，查看每日浏览、保存、定制、扫码、打印和盖章统计。现场使用要点：

- 用 `启动平台（局域网）.bat`（或 `tools/launch_unified.py --lan`）启动，并设置 `WSC_WORKSPACE_PASSWORD`；访问地址应填写主机的局域网 IPv4 地址，海报和二维码按它生成。
- 自助屏在全屏浏览器中打开 `http://主机地址:8030/#section=creative&kiosk=1`。空闲时轮播主题，无人操作到设定时间后自动复位；观众在屏上选好的成品用手机扫码带走，带走码 24 小时有效。`kiosk=0` 可退出自助屏模式。
- 展示大屏打开 `http://主机地址:8030/#section=creative&screen=1`，无需触摸：逐个主题依次展示原石拓片、线描和艺术演绎，旁边是故事和手机扫码二维码（设置了 Wi-Fi 时另附 Wi-Fi 二维码），横屏、竖屏都可以。新上架的主题 10 分钟内自动加入轮播，大屏的浏览不计入统计。
- “场馆与现场”可下载自助屏和展示大屏的启动脚本（`.bat`，写有当前访问地址）。复制到屏幕电脑上双击，脚本会等平台主机可以访问后，用 Edge（没有 Edge 时用 Chrome）在单独的浏览器配置中全屏打开。第一次运行时会询问是否设为开机自动打开，选“是”会复制到“启动”文件夹，并关闭接通电源时的屏幕和系统休眠；也可以带 `/install`、`/uninstall` 参数运行。访问地址改变后需要重新下载脚本。
- 七个展厅各张贴一张印章海报，观众扫码盖章，集齐七枚可领取集章纪念卡。开放打印后，观众可为明信片或整组表情贴纸（一张 148 × 100 mm 贴纸页，沿虚线剪开）领取打印号，工作人员在“场馆与现场”的打印队列中打印；每人同时最多排队两张。
- 观众定制的作品保留 3 天，观众身份与当前浏览器关联，需要保留的成品应及时保存到手机。

主题成品保存在 `resources/creative/themes/<主题>/`，记录保存在 `data/creative.sqlite3`，观众作品在 `data/creative/works`。Seedream 密钥与印章签名密钥保存在本机 `config/creative.json`，不纳入版本管理；更换电脑或 Windows 账户后需要重新配置密钥。在线问答、Seedream 生图与 MiniMax 视频的服务均在“API 配置”中分别设置。

| `resources/reference/报告与说明` | 定级报告、名录与尺寸说明、广陵书社画面说明 |
| `resources/reference/测绘与CAD` | 院落、展厅和周边环境的原始 DWG、DXF、CAD 导出 PDF 与平面示意图 |
| `resources/reference/测绘与CAD/施工图纸` | 汉文化保护传承中心施工图：建筑（2026-09-25，建施-01～20）、结构、暖通、给排水，以及 `9.24武氏祠景观施工图`（土建、绿化） |
| `resources/reference/现场参考照片` | 按展厅、院落部位和周边环境分组的原始参照照片 |
| `resources/reference/演示资料` | 广陵书社提供的三个原始 PPTX，保留图片、文字和原始编排 |

这些原件应随完整项目复制。旧导入路径与测绘来源路径已通过资源映射兼容，档案中的报告、演示资料链接和制作脚本仍能读取原件；无需手动修改历史来源记录。以后新增同类资料优先放入以上分类，改动已登记文件的位置时应同步维护资源映射。

`resources/reference/viewers` 保留仍在使用的原版三维查看器。建模转换得到的 DXF、分析结果和制作中间文件继续保存在 `resources/authoring` 对应工程中；文物研究底图和文献中心原书分别保存在 `resources/stones` 与 `resources/documents`。

### 原图无损收纳

石刻目录 `images` 和 `versions` 下的 TIFF 可无损收纳到 `runtime/resource-packs`，按文物保存为标准 ZIP64 包。包中保留原文件的完整字节；清单记录逻辑路径、SHA-256、原始时间和图像尺寸。压缩工具逐个解压校验成功后才移除对应散文件，不转码、不降低像素或位深。模型贴图、预览图、文献、制作工程和研究数据库保持原存储方式。

收纳后的项目可直接启动。平台、资源扫描、研究底图、素材来源和交接工具通过原逻辑路径访问资料；原图首次使用时自动校验并解压到本机缓存。默认缓存位于 `%LOCALAPPDATA%\WSC-Unified\cache`，无需随项目复制。首次读取大图可能稍慢，本机缓存会随使用增长。完整资源检查会校验压缩包指纹，不会把全部原图解压到项目内。

原图资源包属于必须随项目保留的资料，不能当作临时安装包删除。资源文件夹中看不到已收纳的 TIFF 散文件属于正常情况；需要直接在其他软件中批量操作原文件时，可以恢复原始目录。新放入同一逻辑路径的散文件优先使用，仍须在工作台执行资源检查来确认是否替换已有底图。

以下命令在项目根目录运行。查看计划可随时执行；实际收纳或恢复前先保存研究内容并运行 `tools/停止平台.bat`，完成后用原启动入口重新启动。

```powershell
# 查看尚可收纳的原图与已有压缩包
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tools/compact_resources.py

# 校验后收纳；中断后可以再次执行
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tools/compact_resources.py --apply --workers 4

# 恢复原始散文件，校验后移除不再使用的压缩包
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tools/compact_resources.py --restore
```

两端使用相同版本程序时，散文件与已收纳目录之间仍可顺序交接；收纳本身不改变研究文件指纹或交接基线。恢复原图需要为展开后的原始文件预留磁盘空间，已有不同内容的散文件不会被恢复命令覆盖。

## 增加资料与迁移

已有文物的新照片放入对应 `images/photos`，新拓片放入 `images/research-rubbings`，使用新的文件名。复制完成后，在“图像研究 → 档案维护”执行“重新扫描”或“批量扫描”登记。需要核查重命名、缺失或替换文件时，使用“检查资源”。新文物还需登记稳定编号及身份卡。

新文献放入 `resources/documents/extension`，完成书目与 PDF 登记，再进行文本提取、OCR 和校订。模型权重放入 `models` 后，还需配置运行环境和调用入口才能使用。

### 首次复制到另一台电脑

1. 保存成果，等待计算任务结束或取消任务，运行 `tools/停止平台.bat`。
2. 将整个项目目录复制到目标电脑的本地可写磁盘，包括 `resources`、`models`、`runtime`、`build` 和 `data`。
3. 保留现有 `data/handover.json`，双击 `启动平台.bat`，等待首次环境准备完成。

通过 U 盘传递完整目录时使用 exFAT 或 NTFS，项目包含超过 4 GiB 的单文件。目标电脑需要给项目和本机环境缓存预留空间；本机缓存无需从旧电脑复制。

### 后续交接研究修改

1. 在当前电脑保存成果，运行 `tools/导出研究交接包.bat`，工具会先停止平台并导出 ZIP。
2. 在接收电脑运行 `tools/导入研究交接包.bat`，选择交接包，导入成功后再启动平台。
3. 接收电脑完成下一轮工作后导出新包，其他副本按生成顺序导入。

交接采用顺序接力，同一时间由一个离线副本继续编辑。独立修改产生冲突或跳过前一份包时，导入会停止。包内包含研究数据库及相关改动，不包含日常未变更的全部资源、程序源码、模型权重、运行环境和在线密钥；程序或模型升级需另行同步两端版本。

导入前的备份位于 `data/backups/handover-*`。交接包不能代替定期完整备份，复制完整项目或制作恢复备份时应先正常停止平台。

## 开发与维护

版本为 2.0.0。前端使用 React、TypeScript 和 Vite，后端使用 FastAPI、SQLAlchemy 和 SQLite。普通运行使用 `build/web`，修改前端源码后需执行 `tools/构建前端.bat`，再刷新页面；修改后端后需停止并重新启动平台。

构建工具从 `runtime/development.zip` 准备 Node.js 和依赖，放在本机缓存中。开发与测试命令应在项目根目录执行，使用 `tools/run.ps1` 选择配套环境，例如：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tests/test_annotation_geometry.py
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tests/test_segment_concurrency.py
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tests/test_xcl_layout_concurrency.py
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tests/test_geometry_rendering.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tests/test_xcl_placement.mjs
```

上述回归覆盖几何校验、历史坏数据、并发校订、布局版本、前端显示及草稿保存；写入检查使用临时数据库或临时布局文件。其他模型和集成测试按各脚本参数在隔离数据上执行，避免把试验数据混入正式研究库。

制作工具位于 `tools/authoring`，配方登记在 `config/authoring-recipes.json`。Blender 仅在修改或导出相关制作工程时需要，浏览平台无需安装。

前端的颜色、字体、圆角和阴影集中在 `src/frontend/src/theme.css` 中，以语义变量（`--bg-*`、`--text-*`、`--accent`、`--line` 等）定义深浅两套主题。该文件最后加载，新增页面样式应引用这些变量，不要再写死颜色。

传承中心模型的重建步骤如下，在项目根目录执行：

```powershell
# 1. 施工图 DWG 转 DXF（LibreDWG 0.14 的 dwg2dxf），输出到制作工程目录
dwg2dxf.exe -o resources\authoring\heritage-center\cad-20260925\sg-20260925.dxf "resources\reference\测绘与CAD\施工图纸\施工图_建筑20260925.dwg"
# 2. 提取各平面的轴网配准线稿、门窗与标高文字（需要额外安装 ezdxf，仅制作时使用）
python tools\authoring\extract_center_cad.py
# 3. 由各层平面推导室内墙体、柱、楼梯踏步、楼板和功能分区
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tools/authoring/derive_center_floors.py
# 4. 生成立面材料贴图
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tools/authoring/prepare_center_textures.py
# 5. Blender 5.2 建模并导出 resources/scenes/models/hanwenhua-center-20260925.glb
blender --background --factory-startup --python tools\authoring\build_center_blender.py
```

第 2 步的结果保存在 `resources/authoring/heritage-center/cad-20260925/views.json`。第 3 步生成同目录的 `floors.json`（含各层分区及颜色）；加 `--preview 目录` 可以输出各层检查图。第 5 步同时保存可编辑的 `.blend` 与 `build-report.json`，并写出前端图例用的 `src/frontend/src/center/centerZones.json`。每个网格都带有楼层标签 `center_level`（`B1`、`F1`、`F2`、`RF` 屋顶、`site` 场地）和角色标签 `center_role`，分区地面另带 `zone_id`，前端据此分层、着色和拾取。原 V2 模型保存在 `resources/authoring/heritage-center/v2/`，作为场地与乔木点位来源。重新导出后，需要把新文件的 SHA-256 和新的 `revision` 同时写入 `src/frontend/src/archive/three/hanwenhuaCenterPlacement.json`（同步复制到 `resources/georeferencing/hanwenhua-center-placement.json`）和 `src/frontend/src/center/centerProject.json`，再构建前端。

传承中心模块的项目附属模型（结构、机电、景观、武氏祠白模）在完成上面第 1～5 步后制作：

```powershell
# 6. 结构、暖通、给排水与景观施工图转 DXF
$cad = "resources\reference\测绘与CAD\施工图纸"; $work = "resources\authoring\heritage-center\cad-20260925"
dwg2dxf.exe -o "$work\structure.dxf" "$cad\结构施工图260925.dwg"
dwg2dxf.exe -o "$work\hvac.dxf" "$cad\武氏祠暖通施工图.dwg"
dwg2dxf.exe -o "$work\plumbing.dxf" "$cad\武氏祠汉文化保护传承中心给排水施工图-W.dwg"
dwg2dxf.exe -o "$work\land-base.dxf" "$cad\9.24武氏祠景观施工图\土建\底图base.dwg"
dwg2dxf.exe -o "$work\planting.dxf" "$cad\9.24武氏祠景观施工图\绿化\P2.01-景观绿化施工图09.11_t3.dwg"
# 7. 按轴网配准结构与机电平面，按 CGCS2000 坐标配准景观，提取构件、管线与种植
python tools\authoring\extract_center_disciplines.py
# 8. Blender 建模并导出 resources/scenes/models/hanwenhua-center-project-20260927.glb
blender --background --factory-startup --python tools\authoring\build_center_project_blender.py
```

第 7 步输出同目录的 `disciplines.json` 和前端红线数据 `src/frontend/src/center/centerRedline.json`，景观要素在这一步按红线裁剪；加 `--preview 目录` 可以输出各专业检查图。第 8 步沿用主模型的坐标系和建模函数，武氏祠白模取自院落建筑模型并做体素重建与减面；可编辑的 `.blend` 和 `project-build-report.json` 保存在 `resources/authoring/heritage-center/blender/`。重新导出后，把新文件的 SHA-256 和新的 `revision` 写入 `src/frontend/src/center/centerProject.json`，再构建前端。

展陈装修模型在完成上面第 1～5 步后制作，设计文件放在 `resources/reference/测绘与CAD/施工图纸/武氏祠汉文化保护传承中心项目展陈设计文件9.18改(2).pdf`：

```powershell
# 9. 从设计文件效果图裁切、校正展陈贴图，并生成星空、沙面、石材等可平铺材质
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tools/authoring/prepare_exhibition_textures.py
# 10. Blender 建模并导出 resources/scenes/models/hanwenhua-center-exhibition-20260927.glb
blender --background --factory-startup --python tools\authoring\build_center_exhibition_blender.py
```

第 9 步的贴图和裁切记录 `exhibit-manifest.json`（每张图的页码和裁切范围）保存在 `resources/authoring/heritage-center/textures/`。第 10 步沿用主模型的坐标系和材质函数，按建筑模型中各房间的墙面、柱位布置墙面饰面、展柜、展项、吊顶和灯带，并写出前端展厅数据 `src/frontend/src/center/centerExhibition.json`（章节、页码、房间、人视点与灯光）；可编辑的 `.blend` 保存在 `resources/authoring/heritage-center/blender/传承中心_展陈装修_20260927.blend`。每个网格带 `center_role = fitout`、`center_level` 和 `center_hall`，吊顶另带 `center_part = ceiling`。重新导出后，把新文件的 SHA-256 和新的 `revision` 写入 `src/frontend/src/center/centerProject.json` 的 `models.exhibition`，再构建前端。

院落建筑的配色与鸱尾由 `tools/authoring/refine_courtyard_glb.py` 追加，它以 `resources/authoring/courtyard-refine/before/` 中带交互门扇的模型为底稿，只改材质系数并追加屋面构件，重复执行结果一致。重新制作院落建筑后，应先把新的门扇模型放回该目录，再运行此脚本。

## 图谱与展示资料约定

图谱候选保存在 `config/knowledge-graph/core10-candidates.v1.json`，附原文摘录和持久来源身份。候选提供待核线索，OCR 文段已校订不等于其历史释读已确认；无法唯一映射文物的关联不会强行创建图像标注。同一题材可以关联多个图像区域，各区域保留自己的形状、底图和引用。

摘录保存时会核对来源、归属、字符位置与正文。原文变化或来源不可用时保留记录供核查。维护人员可运行以下只读来源校验，结果输出到 `logs/knowledge-validation.json`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 tools/validate_knowledge_candidates.py
```

`resources/sources/KnowledgeGraph` 是研究参考仓库，不属于平台运行依赖。第三方引擎、参考资料附带的说明及许可保留在各自目录；项目使用与维护说明统一在本 README。

首页正门插画位于 `src/frontend/public/brand/museum-gate.webp`，由用户提供的博物馆实景照片转绘为淡彩建筑线描，用于展示，不作为建筑测绘或历史复原依据。原始文献、拓片、艺术衍生图与已审研究内容保持各自的来源属性。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 双击启动后尚未打开页面 | 首次环境准备需要时间；失败时查看启动窗口及 `logs/platform.log` |
| 提示端口由另一份平台占用 | 先正常停止原目录的平台，再启动当前目录 |
| 启动时提示“平台或交接工具正在使用本目录” | 运行 `tools/停止平台.bat`，等窗口关闭后再启动；如提示平台进程仍未退出，按提示的进程号在任务管理器中结束后再启动 |
| 局域网设备无法访问 | 核对主机地址、局域网启动方式及 Windows 防火墙配置 |
| 写入时要求登录 | 重新登录工作台；平台重启会使原会话失效 |
| 登录提示失败次数过多 | 按提示等待 60 秒，核对密码后再登录 |
| 保存文段或布局时提示冲突 | 保留当前调整，读取最新版本后重新核对并提交 |
| 修改前端后页面仍是旧内容 | 运行 `tools/构建前端.bat`，完成后刷新浏览器；仍显示旧界面时按 Ctrl+F5 强制刷新 |
| 院落全景中的传承中心仍是旧模型 | 确认 `resources/scenes/models/hanwenhua-center-20260925.glb` 存在并已构建前端，然后强制刷新浏览器 |
| 传承中心模块一直显示“正在载入” | 确认 `resources/scenes/models` 中同时有 `hanwenhua-center-20260925.glb`、`hanwenhua-center-project-20260927.glb` 和 `hanwenhua-center-exhibition-20260927.glb`，然后强制刷新浏览器 |
| 换电脑后模型或在线服务不可用 | 核对完整模型与运行包、目标机驱动，并重新填写所需在线密钥 |
